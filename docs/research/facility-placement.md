# Phase 5：既存道路の自転車設備配置

## 研究課題

既存の道路区間から自転車設備を追加する候補を選び、一定の整備延長のもとで、OSMに設備なしと明記された区間の通行量を減らす。現在の20組のODペアは実測需要ではないため、各ペアを1回ずつ通行する仮想需要として扱う。出力は施工提案ではなく、現地調査の優先順位を付けるための実験結果である。

国土交通省の[自転車ネットワーク計画・整備ガイドライン](https://www.mlit.go.jp/road/bicycleuse/guideline/)を道路条件と整備形態の検討時に参照する。ネットワーク全体の連続性や需要を考慮する問題としては、[Bicycle Network Improvement Problem](https://arxiv.org/abs/2107.04451)や[需要を用いた自転車ネットワーク設計の研究](https://www.nature.com/articles/s43588-022-00318-w)がある。

## データの区分

- `cycleway=no`等、設備がないことを明示するタグがあり、設備を示すタグがない区間：今回の候補。
- 設備を示すタグがある区間：整備済みとして候補から除く。
- `cycleway`関連タグがない区間：実際の設備有無は不明。今回の候補・効果計算には含めない。

OSMの明示的な`no`も現地確認済みという意味ではない。整備可能幅員、交通量、事業費、交差点処理、用地・規制は別途調査が必要である。現在の経路比較画面の「自転車レーン率」は従来の広いOSMタグ分類を使用しており、この最適化の「明示的な設備なし」と直接比較しない。

## 最初の数理モデル

対象プロファイルはバランス型とする。ODペア集合を`K`、候補道路区間集合を`E`、ペア`k`の現状経路を`P_k`、区間長を`L_e`、仮想需要を`q_k=1`、整備延長上限を`B`とする。逆方向の有向エッジは同じ道路区間へまとめ、`x_e ∈ {0,1}`を整備するかどうかの変数とする。

```text
最大化   Σ_e (Σ_k q_k · 1[e ∈ P_k]) · L_e · x_e
制約     Σ_e L_e · x_e ≤ B
         x_e ∈ {0,1}
```

これは現状経路を固定した0/1ナップサック問題で、目的値の単位は「仮想通行回数×m」である。候補ごとの通行回数、整備延長、削減見込み、選択結果をCSVへ出す。実装では長さを1 m単位で切り上げて予算制約を厳しめに扱い、動的計画法で離散化後の最適解を求める。元の長さでも予算超過がないことを確認する。

## 整備後の経路再計算

候補選定後、元データの複製上で選定区間を仮に`cycleway=lane`として扱い、全ODのバランス型経路を再計算する。元のGraphMLは変更しない。整備前後の明示的設備なし区間の通行距離、タグ不明区間の通行距離、総経路長、経路が変わったOD数を比較し、`facility_placement_comparison.csv`とWeb画面へ出す。地図は選定区間を橙、未選定候補を灰で示す。

2026年10月16日の東京駅周辺3 kmの実験では、整備延長上限1,000 mで選んだ20区間を仮に整備しても、20組の経路は変わらなかった。明示的設備なし区間の通行距離は1,711.41 mから716.33 mへ減り、総経路距離は55,074.87 mのままだった。これは選択された区間が現状の経路上にあり、整備後も同じ経路が選ばれた結果である。設備タグ不明区間の通行距離は36,408.77 mあり、効果の解釈には大きな制限がある。

## 次の検証

需要データが得られれば`q_k`を実測または推計の通行量へ置き換え、複数予算とプロファイルで結果の頑健性を調べる。現状経路外の候補やネットワーク連続性も評価するには、候補選択と整備後の経路探索を組み合わせたモデルが必要になる。実候補の提示前に現地・公的資料で設備有無と施工可能性を確認する。
